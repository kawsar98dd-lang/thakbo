4. FINDINGS / RECOMMENDATIONS
A. ESLint service-worker override exists in eslint.config.js and includes globals.serviceworker, which is aimed at fixing the prior public/sw.js undefined browser globals. It still needs a real ESLint run on the required Node version to confirm the fix.
B. The theme is initialized in a React useEffect after hydration. This can briefly display the default/light theme before the saved/preferred theme is applied. Low priority; consider a safe pre-hydration initializer only if verified against the current SSR/CSP setup.
C. The install card is shown to eligible non-standalone visitors even before a native beforeinstallprompt event exists; in that case its action is “How to install.” Dismissal is session-scoped, so it may reappear in a later session. This is a UX choice, not a confirmed functional defect.
D. The service worker cache list and manifest icon paths exist in the archive. Confirm the icon artwork and install experience on real Android Chrome/iOS Safari during Preview testing.
E. The security audit only checks repository configuration. The script itself explicitly says it cannot prove production/Preview configuration, secret-store values, or deployed behavior.
